# 宿主支付展示

这是免 CLI 与 CLI 共用的支付展示规则。只使用实际返回的字段和当前宿主明确支持的能力；环境识别仅提供图片格式偏好，不能把终端版当成桌面版。

## 统一展示顺序

1. 所有宿主均使用 Markdown 链接 `[打开支付页面](完整 checkoutUrl)`，将括号内替换为实际返回的完整 URL；不输出裸 URL，不放进代码块，也不称为备用链接。账号订单只有 `paymentUrl` 时使用原值，并说明需要下单的同一账号登录。链接位于输出外层，不在 `paymentPresentation` 中；通用 Commerce 命令返回同源 `paymentPresentationGuide`，二维码字段位于 `order.paymentPresentation`；保留完整 URL，不猜补或改写。链接缺失时报告，保留原订单，不为获取链接另建订单。
2. 宿主支持聊天图片且返回 `paymentPresentation.imagePath` 时，优先展示本地 PNG。同一回复正文中，同一订单只嵌入一张二维码图片。本地图片不可用或明确失败时，才使用宿主独立允许的 HTTPS 图片通道展示 `checkoutImageUrl`；不要下载远程图片绕过宿主限制。图片不能替代官方支付链接。
3. 实际存在内置浏览器工具时，调用该工具在当前任务内打开同一官方支付链接。链接和聊天图片与网页预览可以同时展示。没有内置浏览器或打开失败时，保留聊天图片和可点击链接，让用户扫码或自行点击；不要自动启动外部浏览器，也不要声称页面已经打开。工具返回 queued 不等于已加载。

官方收银台只读查询当前订单，并在服务端确认到账后原地显示「已支付」。聊天二维码是静态图片，不代表最新订单状态。付款成功不等于安装完成；权益、下载安装和恢复由原购买命令确认。

## 各宿主的图片与浏览器能力

- **Codex Desktop**：本地图片写成 `![微信支付二维码](<imagePath>)`，替换为实际绝对路径，不使用 `local-file://`。使用当前宿主提供的内置浏览器能力，在当前任务内打开返回的完整支付链接；不能只写链接代替打开操作。
- **WorkBuddy**：本地图片写成 `![微信支付二维码](<imageChatSrc>)`，使用返回的 `local-file://` 地址，不用裸文件路径。在同一轮调用 `present_files({"files":[完整 checkoutUrl],"cwd":当前工作目录的绝对路径,"explanation":"打开官方支付页面"})`，将示例值替换为实际值，在右侧内置浏览器打开官方支付页；`files` 传完整支付 URL，不传 PNG、本地 HTML 或 `widgetPath`。工具未直接列出时，先用 `ToolSearch` 查找 `present_files`，按返回 schema 直接调用或通过 `DeferExecuteTool` 执行；不能因首屏工具清单未列出就跳过。只有发现工具确实不可用或调用失败时才降级为聊天二维码和 Markdown 链接，并如实说明页面未打开。
- **豆包工作**：不根据平台名称假定支持本地聊天图片；遵循实际获准的图片与内置浏览器能力，始终保留链接。
- **Codex 终端版、Claude 与未知宿主**：始终交付官方链接，图片与网页预览只在能力明确可用时使用；不假定存在桌面预览。

本地付款 HTML 已退役：不生成、不展示 `widgetPath`，不生成 HTML 付款卡片，也不通过 `show_widget` 展示付款卡片。这不禁止 WorkBuddy 使用 `present_files` 打开官方 HTTPS 支付 URL。不要读取支付凭证、重画二维码、拼接 URL 或向第三方上传支付数据。其他用途的 Widget 不受影响。

## 展示结果与等待边界

先实际交付二维码或可点击官方链接，再启动原购买流程的有界等待；不要提前在后台启动等待。仅生成图片文件或返回本地路径不算展示成功。保留同一订单和原身份继续查询；网络失败、倒计时结束或用户自述都不是付款结果，也不能作为重新下单的依据。

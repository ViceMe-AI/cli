# 个人名片更新与源稿恢复设计

## 目标

让已发布个人名片的创作者在对话中拥有两条清楚、可验证的更新路径，并始终保留原个人页
路由：

1. **修改当前版本**：在当前名片基础上修改资料、作品、链接或经用户确认的局部视觉调整。
2. **重新制作一版**：重新从正式模板册或用户拥有的网站来源开始，完成后替换当前名片。

右侧只用于查看当前页面、模板和本机预览；选择、资料输入与确认全部在对话中进行。用户不
会看到 CLI、源稿路径、Merchant、release ID 或内部状态。

## 已有能力与边界

现有 `merchant page` 流程可以：描述目标、检查 ZIP、上传、发布到同一页面路由、读取发布状
态和回滚历史版本。因此“重新制作一版并替换同一路由”可以由当前 Skill 完成。

现有 CLI/API 没有“下载当前已发布个人页的原始项目”的契约。线上 HTML、截图或渲染后的
Profile Blocks 不能视为模板工程的可编辑源码。Agent 不得抓取或反编译公开页面后，宣称已
恢复用户的源稿。

## 用户入口与状态机

用户说“更新我的名片”“修改个人名片”或同义语时，先执行现有资格与目标归属检查，并读取
当前个人页。随后给出两项选择：

```text
你的名片正在使用中。你想：
1. 修改当前版本：更新头像、介绍、作品、链接或局部内容；
2. 重新制作一版：从模板或导入主页开始，完成后替换现在的名片。
```

### 修改当前版本

只有平台返回当前 active release 为可恢复源稿时，此选项可进入编辑：

1. 平台验证当前用户拥有该页，将该版本的源稿恢复到一个本机临时工作目录。
2. Agent 告诉用户“已带回上一版名片”，收集本次修改内容；不要求再次选择模板。
3. 若用户改变公开范围，集中确认新的公开范围一次；否则直接制作本机草稿。
4. Agent 打开本机预览，用户确认该预览一次。
5. Agent 基于恢复前读取的 active release 上传并发布新版本到原路由。

若源稿不可恢复，Agent 不提供虚假的“修改当前版本”。它说明可选方案：导入用户保存的原始
项目/ZIP，或以当前信息为参考走“重新制作一版”。

### 重新制作一版

流程沿用创作者个人名片入驻流程：查看正式云端模板册，或导入用户拥有/获授权的主页，或参
考他人主页的结构与视觉但不复制内容。没有空白“完全自定义”路径。

旧页面在新版本预览及用户最终确认之前持续在线。确认后，新 release 原子替换同一
`profileUrl`；审核中的创作者仍只对本人可见，获批后由平台在同一路径自动公开。

无论使用正式模板、原样导入自己的主页或参考别人的主页，三条来源都要进入同一个完成阶段：
先分析已有内容，再输出“可直接使用 / 待确认公开 / 缺失”。原样导入必须保留用户已有的内容、
结构和视觉，不能要求用户重复提交页面中已经存在的资料；只针对真正缺失或公开范围不明的内容
集中追问。资料与公开范围明确后才创建最终本机预览，且只有该预览获得一次确认后才更新页面。

## 平台恢复 Contract

恢复能力属于 CLI/API 与页面发布存储，不属于 Skill。实现可采用下列等价命令，但必须保持
相同语义：

```text
viceme merchant page source status --target <profileUrl> --merchant <merchant>
viceme merchant page source restore <release-id> --destination <workspace> --merchant <merchant>
```

`source status` 的机器输出至少应包含：

- 当前 active release 与乐观并发 token；
- `RESTORABLE`、`LOCAL_SOURCE_REQUIRED` 或 `UNAVAILABLE` 的恢复状态；
- 已验证的模板 ID/版本（如适用）、源稿校验值与创建时间；
- 页面归属验证结果。

`source restore` 必须只允许页面 owner 恢复其可恢复版本，返回经校验的本机源稿目录及其版本
标识。它不得返回签名 URL、其他用户源稿、凭证或任意历史页面内容。

每次上传并发布个人名片时，平台应同时保存仅 owner 可恢复的不可变源稿快照，包含：源码
archive、模板 ID/版本（如有）、源码 SHA-256、发布 release ID 和生成时间。平台可设置合
理的保留策略，但在删除可恢复源稿前应让 `source status` 可靠地返回不可恢复状态。

## 并发与手动编辑

Profile Blocks 手动编辑与 Agent 本机草稿不是共享草稿。发布更新必须传入恢复时读取的当前
active release / 并发 token；如果其间用户或其他入口已更新页面，平台拒绝覆盖。Agent 只
提示“名片刚刚有新的修改，请重新读取后再合并”，不得静默覆盖或自动重试发布。

第一期不做 Agent 与右侧 Block 编辑器的双向同步。

## Skill 变更范围

在 Contract 可用前，Skill：

- 提供“修改当前版本 / 重新制作一版”的自然语言入口；
- 对不可恢复源稿将“修改当前版本”安全降级到导入原项目或重新制作；
- 保持模板优先、四类资料一次性收集、本机预览和单次最终确认；
- 不调用不存在的恢复命令，不承诺云端共享草稿。

在 Contract 可用后，Skill 仅在 `RESTORABLE` 时调用恢复命令，再进入本机编辑、预览和同路由
发布。新发布的模板名片会自动成为下一次可恢复的源稿版本。

## 验收

- 有可恢复源稿的创作者可以修改并在同一 URL 更新名片。
- 没有可恢复源稿时，用户不会被误导为“已找回源码”。
- 重新制作不会在最终确认前改变现有公开页。
- 手动编辑和 Agent 更新冲突时不会产生静默覆盖。
- 申请中私人可见、审核后自动公开与当前入驻流程一致。
- 仅在本机预览确认后发布；不存在“创建草稿”和“发布”的重复确认。

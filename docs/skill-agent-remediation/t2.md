## 当前产品合同

发布预览不再是一条专用试跑链路：

1. `confirm_steps` 先在 Agent Host 中确认交互步骤，此时没有分享链接。
2. `confirm_publish` 返回仅当前创作者可访问的
   `preview_share_url=/p/{code}`；它与正式分享资源隔离。
3. 创作者在与正式分享页复用体验的私有预览页中完成一次成功运行，再回到
   Agent Host 明确确认或取消。
4. CLI 只负责读取冻结摘要、自然语言编辑、typed action 决议和有界状态恢复；
   不提供 `job run`、`job run-get`、`job accept`，也不实现页面编辑器。
5. 确认后继续等待到 `share_published`，返回正式 `/v/{code}` `share_url`；
   发布后旧 `/p/{code}` 会重定向到该地址，但两者不是同一资源或同一 URL。
6. `confirm_steps` / `confirm_publish` action 过期时，必须在同一
   Publication 和冻结 Candidate 上显式续签：先 `job get` 确认当前过期 action，
   再 `job renew <publication-id> --action-id <expired-action-id>`，从返回的
   `next_action` 继续；禁止重新 inspect/publish 或创建新 Publication。
7. 新会话重新 inspect 同一来源时，若
   `destination.recovery.mode=resume_existing_publication`，必须使用返回的
   `publication_id` 执行 `job get` 并继续原任务；inspect 不复制 action/digest，
   也不得用新的 resolution 再创建 Publication。

首次发布待确认时，只有创作者能看到 pending Candidate；更新发布待确认时，
其他访问者继续看到当前正式 Release。

## 预览产物生命周期

预览阶段产生的输入、输出、文件、媒体、分享会话、Runner 事件和 workspace
历史都是临时数据。确认发布、取消、过期、被新 Candidate 取代或 Release
提交后，服务端都会清理这些数据；它们不进入公开浏览量、使用量、作品或历史。

CLI/Agent Skill 必须明确告知用户：预览结果不会在发布后保留；需要长期保留的
结果，应在正式发布后重新运行。

## 保留的安全合同

- 用户自然语言编辑只能通过 `job edit --request-stdin` 的 subprocess stdin
  传输，不能进入命令字符串、argv、环境变量或 shell 管道。
- metadata 修改使用 `job metadata --edits-stdin` 的结构化 JSON。
- edit 轮询超时必须返回同一 `edit_id` 和 `meta.wait_timed_out=true`；
  通过 `job edit-get` 恢复，不能重复提交编辑。
- `job resume --decision` 必须绑定 action payload、Release Candidate 和公开摘要
  三个 digest。
- 409 `preview_share_run_required` 只表示稳定链接上尚无一次成功普通运行；
  应继续使用同一链接，不能创建额外 PreviewRun。
- action 续签必须显式绑定 Publication ID 和已过期 action ID；CLI 不做隐式
  自动续签，也不把 terminal `failed`、`unsupported`、`rejected` 等结果当成
  可续签动作。资格校验由服务端统一拥有。

## 验收范围

- Cobra 命令面、API 客户端类型和命令清单均不存在旧 PreviewRun 命令。
- 内置 Skill、中文/英文 README、commands/statuses 文档统一使用
  `preview_share_url`。
- 覆盖确认步骤后才签发稳定链接、链接字段透传、自然语言编辑安全传输、
  edit 超时恢复、过期确认 action 原地续签的正反向边界，以及命令清单无漂移。
- `go test ./...`、`make skill-check`、`make command-manifest` 通过。

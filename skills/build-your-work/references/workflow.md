# 整理工作流

## 识别现有 Skill

目录输入或安全检查后的 ZIP 中存在唯一 Skill 根，并且该根级有 `SKILL.md` 时，按现有 Skill 处理。ZIP 必须先检查所有 entry 名称、类型、大小、重复项、加密标志和压缩比，确认没有绝对路径、`..`、反斜杠、符号链接或特殊文件后，才能解压到 `viceme-dist/staging/`。

保真模式应：

- 保留合规的 `name`、`description` 与正文；
- 保留正文引用的必要文件和原有有用结构；
- 排除禁止内容和无关构建产物；
- 检查净化后所有相对引用仍有效；
- 只在 frontmatter 不合规、根结构无法识别、引用因净化失效或用户明确要求优化时修改 staging 副本。

优化前先理解原 Skill 的用途和触发条件。不得改变核心能力、扩大权限或加入无关工作流。

## 识别网站

没有 Skill 根时，只读取入口、清单、锁文件、构建配置和直接相关文件来判断网站类型，不遍历阅读全部源码。

### 可直接运行的静态网站

入口及关键资源无需依赖安装或编译即可运行时，将需要的运行文件复制到 staging，再映射为 `package-root/site/`。保持原目录层级，不执行无意义的安装或构建。

### 需要构建的网站

在 `viceme-dist/staging/source/` 的隔离副本中使用项目已经声明的包管理器、锁文件和构建命令构建一次：

- 不迁移框架，不发明新的构建命令；
- 不读取父级 workspace 配置；
- 将包管理器 cache、临时文件和 HOME 类状态定向到 `viceme-dist/`；
- 实际部署产物的根目录映射到 `package-root/site/` 根，内部文件名、子目录与相对引用保持不变；
- 不把 `node_modules`、开发缓存、源码依赖或构建工具本身放入 `site/`。

只允许在 staging 中进行不改变体验的部署适配，例如修复静态资源相对 base path、注入公开且非敏感的运行配置、移除 source map、缓存与开发日志。不得改写作品标题、品牌、文案、角色、数据、视觉主题、主要布局和核心交互。

如果作品本质依赖后端、私有 API、密钥或不可离线提供的服务，准确记录运行依赖。缺失依赖会让核心体验消失时，不得用静态假页面冒充完整 Site。

## 建立保真基线

创作者提供网址时，使用宿主已有浏览器能力观察公开页面的标题、视觉层级、主要内容和一条核心交互，并与项目构建产物核对。公开网址只提供可见行为参考；不得把截图、在线 HTML 或猜测出的源码直接冒充完整项目。网址不可访问时，继续以本地项目为依据并标注未核对；只有网址而无可构建项目或合法导出文件时，停止打包并说明所需输入。

在修改 staging 前，使用宿主已有能力运行原作品一次，记录入口、标题、主要画面、关键内容和主要交互。运行能力不可用时，从入口和关键资源建立静态基线并标明限制，不为此安装工具。

最终 `site/` 必须与这条基线保持同一作品身份：

- 名称、主题、品牌和核心内容一致；
- CORE 交互、反馈和关键动画一致；
- 主要视觉层级与内容结构一致；
- 用户完成主要体验的路径一致。

构建工具产生的 hash、bundle、压缩等非语义差异可以接受。因子路径部署进行的必要资源路径适配也可以接受。

## 可编辑参考与资产

编译后的 bundle 适合运行但未必适合 Agent 阅读。只有仅凭 Skill 方法和 Site 资产无法稳定复现核心效果时，才额外提供精简 `template/` 或 `references/implementation.md`；不要复制整个原始仓库。

`assets/` 只存真正有助于继续创作且允许分发的资产。已经存在于 `site/` 的文件默认不再复制；需要复用时直接引用包内 `site/` 路径。为重要资产说明用途、适用场景、可修改边界和不应复用的情况。

# 项目边界与源文件完整性

## 确定边界

`PROJECT_ROOT` 只由用户明确给出的当前项目目录或 Skill 被调用时的当前工作目录确定一次。不要读取外层 `.env`、其他网站、历史备份、同名目录或服务端项目来补充上下文。

所有文件参数使用 `PROJECT_ROOT` 内的相对路径。绝对路径只有在宿主已经提供且规范化后仍位于 `PROJECT_ROOT` 内时才可用于确定该根；后续业务命令仍使用相对路径。拒绝包含 `..` 的输入路径，不跟随任何符号链接。

Skill 自身的已安装脚本可以作为工具执行，但其业务输入和输出必须限制在 `PROJECT_ROOT/viceme-dist/`。不得让脚本扫描 Skill 安装目录或其他项目内容。

## 记录原始状态

开始和结束都排除根级 `viceme-dist/`。

- 只有 `PROJECT_ROOT/.git` 自身存在时才使用 Git。调用时设置不向父目录发现仓库的边界，并只比较当前目录状态；不要切换分支、提交、清理或恢复文件。
- 非 Git 项目记录当前目录内每个普通文件的相对路径、大小与修改时间。仅对前后出现差异的原文件计算摘要，避免无意义地读取全部内容。
- 记录现有符号链接本身，但不读取其目标。任何需要跟随链接才能构建的项目都属于阻塞。

如果打包期间用户或其他进程修改了源项目，报告差异；不得覆盖、回滚或把变化归因于打包工具。

## 隔离构建

创作者源文件只读。将构建所需文件复制到 `viceme-dist/staging/source/`，忽略 `viceme-dist/` 本身和包合同中的禁止内容。复制时拒绝符号链接与特殊文件。

依赖安装、构建缓存、临时 HOME、包管理器 store 与工具输出全部定向到 `viceme-dist/`。如果项目依赖父级 workspace、`../` 文件依赖、全局私有配置或外部本地路径，不要读取这些路径；说明项目无法在当前边界内独立构建。

不要为验证安装新的浏览器、Agent、截图器或审计工具。复用宿主已有能力；缺少非必需能力时做静态验证并明确报告。

## 清理

打包成功并完成验证后，只删除本次在 `viceme-dist/` 下生成的 staging、cache 和检查目录。不要用未解析的 glob 或宽泛递归删除命令。默认保留 `viceme-dist/package.zip`，以及用户明确要求保留的报告或截图。

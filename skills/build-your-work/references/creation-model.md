# Creation Skill 创作模型

## 消费者体验

消费者应能从“看到作品”自然进入“我也想做一个自己的版本”：用自然语言描述想法后，Agent 直接建立可运行结果、展示体验并继续迭代。不要要求消费者先阅读完整 Skill、理解目录结构、研究原项目、自己寻找默认素材、指定框架或先完成教程。

## CORE 与 VARIABLE

先根据原作品和用户意图明确两类信息：

- **CORE**：失去后作品不再具有核心体验的交互、动画或物理机制、关键视觉结构与空间关系、反馈方式、内容呈现方式和体验节奏。
- **VARIABLE**：可围绕用户想法变化的主题、故事、文案、图片、数据、配色、字体、品牌、场景、角色和具体素材。

用户没有要求改变 CORE 时保留它；只修改用户点名的 VARIABLE，不顺手重建整个作品。“做一个类似的”表示复用创作方法、体验机制和质量标准，不表示复制原品牌、文案或受保护内容。

## 为网站编写包内 SKILL.md

包内 `SKILL.md` 面向 AI Coding Agent，不是消费者教程。frontmatter 必须包含：

```yaml
---
name: <最多 64 字符的小写字母、数字和单连字符标识>
description: <能创造什么、何时使用；最多 500 字符>
---
```

正文沉淀会改变 Agent 决策的信息：

- 默认创作成果与完整体验；
- CORE、VARIABLE 及二者的修改边界；
- 页面、组件、状态、交互和动画之间的关系；
- 重要视觉规则、参数与资产用途；
- 何时复用 Site 的实现，何时重新创作；
- 常见降质错误；
- 如何构建、运行、展示和验证新作品；
- 后续自然语言修改如何应用到当前结果，而不是从头开始。

避免机械的长篇步骤教程。详细实现、资产说明或验收规则确有必要时放进 `references/`，并在入口说明何时读取。不要创建空 reference。

面向消费者的内容不得使用“逆向”“反编译”“还原”“Reverse Engineering”或暗示未经授权复制的叙事。需要保留的许可、署名和来源信息必须准确保留。

## START.md 与 Agent 元数据

生成简短 `START.md`：说明作品可以继续创作成自己的版本，提供一条贴合当前作品 CORE 与 VARIABLE 的自然启动口令，必要时列出少量可替换想法。不要写教程，也不要机械复用固定句式。

生成 `agents/openai.yaml`：

```yaml
interface:
  display_name: "<消费者看到的能力名称>"
  short_description: "<简短说明能创作什么>"
  default_prompt: "使用 $<skill-name> 帮我创作一个属于我的版本。"
```

所有字符串加引号，`default_prompt` 必须明确提到 `$<skill-name>`。包内 Skill 应规定：用户尚未给出具体主题时读取 `START.md` 并自然地帮助开始；目标已经明确时直接创作，不强迫先读 START 或教程。

## Agent 的默认创作行为

Agent 应建立完整页面、视觉、交互和内容骨架，正确复用方法与资产，保留未被要求改变的 CORE，并围绕用户想法修改 VARIABLE。主动处理视觉层次、排版、间距、动效节奏、响应式、性能和边界情况；实际运行并检查核心交互、动画和资源；优先展示可直接体验的结果。信息足够时直接开始，只有缺失信息会实质改变方向时才集中询问。

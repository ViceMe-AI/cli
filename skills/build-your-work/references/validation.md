# 验证与交付

## 结构与安全

使用 `scripts/package_creation.py` 从准备好的 `viceme-dist/staging/package-root/` 生成最终 ZIP。脚本负责检查 frontmatter、路径、数量、大小、特殊文件、禁止内容、常见密钥、压缩比和确定性 ZIP 元数据，并在写入后重新读取归档验证。

脚本成功不等于 Site 体验已经验证；仍需完成下列人工或宿主能力检查。

## Site 验证

网站转换至少核对：

- 需要编译的项目，其实际构建命令成功；静态站没有执行无意义构建；
- `site/` 入口实际存在，最终包只引用包内文件；
- 页面没有已观察到的阻塞运行错误，关键资产正确加载；
- CORE 交互和关键动画可用；
- `site/` 相对原部署产物没有扁平化、任意改名、移动或丢失运行文件；
- 相同关键状态下，标题、主要画面、核心内容、资产和交互结果与原作品基线一致；
- 原作品若能直接开始体验，Site 不得新增素材选择、上传或额外配置步骤。

使用宿主已有浏览器能力，在一个代表性视口走一次主要体验路径。只有移动端是核心或用户明确要求时再增加移动端检查。浏览器能力不可用时，不安装工具；改做入口、引用和静态资源检查，并明确标记运行验证未完成。

## 可选行为试创作

基础打包不做试创作。只有用户明确要求，或包内 Skill 的核心方法经过实质重写且静态检查不足以判断时，才在 `viceme-dist/` 内用一个不同主题做有界试创作。检查 Agent 能否直接开始、区分 CORE/VARIABLE、复用合适资产、保持核心体验、继续响应一次自然语言修改，并实际运行结果。

生成 creator tutorial 时，抽查内容来自当前可见会话、明确授权会话或明确标注的最终作品归纳；不得含凭据、个人信息、内部指令、隐藏推理或无关会话内容。

## 源项目复核

重复开始时采用的状态记录，继续排除 `viceme-dist/`。确认没有由打包操作造成的原文件新增、删除或内容变化，并确认所有项目内容读取都位于 `PROJECT_ROOT`。用户或其他进程的并发修改单独报告，不覆盖。

## 交付报告

简短报告：

- 输入类型：现有 Skill / 网站转换；
- Skill name；
- ZIP 相对路径、压缩大小、文件数与解压大小；
- Site 入口、构建命令或静态来源、源产物到 `site/` 的目录映射；
- CORE 摘要；
- creator tutorial 是否生成及依据；
- 构建、整理、验证和压缩的大致耗时及异常慢步骤；
- 已实际完成的检查；
- 未验证边界与公开运行依赖；
- 排除的敏感或无关文件；
- 文件系统访问范围与源项目完整性结果；
- 原作品与 Site 的目录及保真对比结果；
- 可选发布素材是否准备。

不要列出密钥内容、内部工具噪声或未执行检查的虚假通过结论。成功后默认只保留 `viceme-dist/<skill-name>.zip`。随后可集中询问一次是否要整理网页发布资料；跳过不影响已完成的 ZIP。若创作者已提供展示标题、简介、价格、币种、试用次数或现成素材，把确认过的资料写到包外 `viceme-dist/publish-notes.md`，记录对应网页字段和仍需人工确认的值，不把资料放进买家 ZIP，不自动填写或提交网页发布。

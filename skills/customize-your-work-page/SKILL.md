# 自定义 ViceMe Skill 作品页

首次调用 CLI 或判断 CLI 不存在前，必须先按 [creator-tools 的 CLI 定位流程](../creator-tools/SKILL.md#cli-定位) 查找现有 CLI；后续使用返回的完整路径。不得只凭 `command not found` 判定未安装或改走免 CLI 流程。

本 Skill 只处理 `kind=SKILL` 且已经发布的作品详情页。用户决定页面内容、视觉和按钮；作品已有的
点赞、评论、获取或购买、作者订阅等真实状态继续由 ViceMe 提供。页面不是在给作品增加新功能，
而是把已有操作用用户选择的方式重新呈现。内部调用方法按需阅读
[作品页数据与操作](references/work-runtime-api.md)，导入现有页面时阅读
[导入与路径适配](references/import-routing.md)。

## 用户可见表达

面向用户的文字跟随当前语言。中文必须使用普通用户能直接理解的表达，只说“这个作品”、
“作品页”、“页面里的按钮”、“预览页面”和“正式使用”。不得向用户展示或解释 CLI、API、SDK、
Block、capability、manifest、iframe、release、Merchant、JSON、权限名、账号 ID、错误码或原始响应，
也不得说“接入点赞接口”“添加购买能力”。内部命令和技术名只允许出现在 Agent 的执行过程。

不要给任何选项标“推荐”，不要替用户选择。用户已经明确页面来源、风格或按钮要求时直接沿用，
不得为了展示选项而重复询问。

## 入口与目标

### 从 `$sell-a-skill` 接续

只接受同一发布流程刚刚返回的准确公开作品 URL 和已确认 Merchant。直接复用这两个值，不让用户
复制口令、粘贴链接、重新选择作品或再次走创作者资格流程；`describe` 仍会重新校验当前登录者和
作品归属。

### 用户单独发起

先以玩法守卫模式调用 `$become-a-creator`。只有它返回当前用户拥有的有效 Merchant 才继续。
用户已经给出准确作品 URL 时直接使用；没有 URL 时运行
`viceme merchant work list --merchant <商家ID>`，只保留 `kind=SKILL` 且 `status=PUBLISHED` 的作品：

- 只有一个时直接使用，不再询问。
- 有多个时用作品标题显示单选项，不展示 ID、slug 或内部状态；同时允许用户输入作品名称。
- 没有时说明“你还没有可以自定义的 Skill 作品页”，然后停止。

用户只要求改标题、简介、封面、价格、试用次数或 Skill 内容时停止本 Skill，并交回对应的发布或
更新流程。只有修改整个页面、排版、视觉或按钮时才继续。

运行 `viceme merchant page describe --target <准确URL> --merchant <商家ID>`。目标不是已发布的
Skill 作品页时，用白话说明当前只支持 Skill 作品页并停止，不尝试网站或其他作品类型。

## 页面制作路径

先从用户已经说过的话和当前工作区判断路径。意图明确时直接执行；只有确实不明确时，才使用当前
Agent 的原生结构化单选工具询问：

> 你想怎么制作这个作品页？也可以直接写下你想要的效果。

选项恰好为：

1. `AI 帮我重新设计` — 根据当前作品内容重新安排整个页面。
2. `在默认页面上改一改` — 保留大致结构，调整颜色、字体、内容排布和按钮。
3. `使用我已有的网页` — 使用用户提供的项目、网页目录、ZIP 或参考页面。

不得给任何选项增加“推荐”标记。结构化工具支持自定义输入时必须保留该入口；有的工具会自动附加
“其他”，不要重复创建第四个选项。工具不支持自定义输入或当前环境没有结构化提问工具时，用同一
句话和三个编号选项提问，并补一句“也可以直接说你想要的样子”。

用户的自由文字同时是路径选择和设计说明，必须保留原意并直接归类：

- 只有风格、结构或按钮描述：进入 `AI 帮我重新设计`。
- 明确说基于默认页小改：进入 `在默认页面上改一改`。
- 给出本地项目、目录、ZIP 或自己拥有的网页：进入 `使用我已有的网页`。
- 同时给出来源和修改要求：使用该来源并直接应用要求，不再问一次。

只有缺少实际文件、路径或必要素材时才补问一个具体输入，不得先让用户选“我要填写”，再问第二次。

### AI 帮我重新设计

用户已经描述风格时直接制作。没有任何设计方向时，再使用一次中立的结构化单选问题：

> 你希望别人打开页面后，第一眼看到什么？也可以直接描述你想要的样子。

选项恰好为：`先看这个 Skill 有什么用`、`先看图片和使用效果`、`页面尽量简单`。同样不得标记
推荐，并保留自由输入。随后用一句白话说明准备采用的内容顺序和按钮位置，直接开始制作，不再索取
一次确认。

### 在默认页面上改一改

根据本次作品数据重新制作一版接近默认信息结构的页面，不抓取、复制或修改 ViceMe Web 源码。
用户没有说具体改动时，只问“你最想改哪里？可以直接说颜色、排版、文字或按钮位置。”，允许自由
输入；不再用技术方案让用户选择。

### 使用我已有的网页

当前工作区已有明确网页项目时直接读取并告知用户“我找到了当前网页，会保留它原来的样子，再按
你的要求修改”。否则只问“请把网页文件、压缩包、项目位置或参考页面发给我。”

目录、ZIP 或仓库必须由用户拥有或明确授权；公开页面只能作为视觉和结构参考，不能反推或克隆其
源码、文案、图片或品牌素材。有源码时复用其技术栈和构建流程；只有静态产物时不要强行补造源码。

## 页面和按钮

先读取这次 `describe` 返回的真实说明，并按
[作品页数据与操作](references/work-runtime-api.md) 把相关调用补足成组行为。这些说明只供 Agent
实现，不向用户展示，也不转成一轮“选择功能”的问题。

除非用户明确要求隐藏，页面默认继续呈现当前作品适用的作品信息、作者信息、点赞、评论、获取或
购买及作者订阅入口。用户可以决定按钮是否展示、位置、顺序、文字、图标、颜色、大小和打开方式。
页面实际出现的按钮必须满足：

- 点赞同时实现初始状态、点赞和取消点赞；刷新后重新读取真实状态。
- 评论至少能读取列表；页面提供发评论或回复时，同时处理未登录状态和失败提示。
- 获取或购买按钮只使用当前作品返回的真实条目；免费、付费、试用、不可购买和多个版本不得混淆。
- 作者订阅只在当前作品上下文允许时展示并打开真实流程。
- 需要登录的动作失败时给出用户能看懂的提示，并允许登录后返回当前页面。
- 不用本地假数据伪造成功、数量、价格、登录或购买状态。

在 ZIP 根目录放置 `viceme-page.json`，`kind` 必须是 `WorkPage`，只声明页面实际使用的平台能力；
不要为了省事声明全部能力。

## 预览、确认与发布

1. 有源码时先运行项目自己的 build。导入页面按
   [导入与路径适配](references/import-routing.md) 检查嵌套路径、资源和页面内跳转。
2. 运行 `viceme merchant page inspect --path <zip>`，只修复包结构和声明不一致问题。
3. 运行 `viceme merchant page preview --path <zip> --target <准确URL> --merchant <商家ID>`，打开返回的
   完整预览 URL，并把同一 URL 作为 Markdown 备用链接。对用户只说：“新页面已经打开，你可以看看
   整体效果、按钮位置和文字是否合适。”
4. Agent 在预览中自行检查电脑和手机布局、首页、页面内跳转和刷新；检查点赞初始状态与可逆切换后
   恢复原状态，检查评论列表和未登录提示，核对免费、付费、试用、不可购买及多版本按钮。不得为了
   验收擅自发表公开评论、创建订单或购买订阅。
5. 最终预览只问一次，使用中立选项：`就用这个页面`、`继续修改`、`先不使用`，同时允许用户直接
   输入修改意见。用户选择继续修改时更新同一份本地项目并重新预览，不重新询问制作路径。
6. 只有用户选择“就用这个页面”或用自由文字明确同意后，才读取 status，并用这次预览的 release ID
   与真实 active release 运行
   `viceme merchant page publish <release-id> --expected-active <当前ID或none> --merchant <商家ID>`。
   不得把开始制作或先前发布 Skill 的确认当作页面发布确认。
7. 发布后打开最初确认的准确作品 URL，重新检查页面、刷新和实际出现的按钮。失败时保留默认页面或
   上一个正常版本，不宣布完成，不自动循环发布。

用户明确要求更新或回滚作品页时，先读取 status，再对准确 release 执行 preview、publish 或 activate；
不自行拼接链接，不把另一个作品的预览或 release 用到当前作品。

## 不变量

- 只通过 `viceme` 访问 ViceMe，不读取配置文件、Token、Cookie 或本地凭证。
- CLI 输出保持机器可读；选项、自由输入和所有用户引导都由当前 Agent 完成。
- 用户修改页面不等于修改作品资料、价格、发布内容或开通新能力。
- 页面包通过结构检查后就允许上传；浏览器的 CORS、混合内容或第三方服务限制在预览中处理，不能
  升级成额外的上传禁令。

# WorkBuddy 本地作品预览刷新

仅在向用户展示本次正在修改的本地网站时读取。登录、授权、支付、签名链接及正式作品 URL 保持原样，不应用本规则，也不新增发布或用户确认步骤。

## 展示与刷新

1. 使用项目真实入口和现有启动方式，复用本任务的开发服务。纯静态 HTML 没有服务时才启动仅监听 loopback 的静态服务，保留原目录结构和文件名；需要构建的项目先更新产物。不要重命名 `index.html`、创建预览包装页或把 URL 查询参数拼到磁盘文件路径上。
2. 展示实际本地 HTTP URL，不重复提交裸 HTML 文件路径来期待强制刷新。首次展示及每批修改完成后，用 URL API 或标准库更新一个查询参数：做同款按钮预览更新已有 `creatorPreview`，其他本地作品预览使用 `previewRev`。每批修改使用新值（如时间戳加递增序号），替换旧值而非不断追加；保留原路径、其他查询参数及 hash 路由，参数放在 `#` 前。不要只改 hash 或额外添加第二个刷新参数。
3. 使用当前会话实际暴露的 `present_files` schema，把新 URL 放入 `files`，`cwd` 使用真实项目目录，`explanation` 简短说明本次展示。工具未暴露时先搜索，不猜测 `force`、`refresh` 等参数。修改后重新调用展示工具，不能只在正文说已刷新；不要用系统默认浏览器代替右侧预览。其他宿主使用其实际提供的面向用户预览能力。
4. URL 尾缀只改变顶层页面地址，不会自动刷新同名 CSS、JS、图片或 Service Worker 缓存。优先复用开发服务的热更新与禁用缓存配置；自建静态预览服务对 HTML 及子资源返回 `Cache-Control: no-store`，避免返回旧的 304。仅在本地开发模式处理 Service Worker 缓存或禁用其注册，不清空用户全局浏览器数据、不修改生产缓存策略。原服务无法保证资源更新时报告具体限制，不宣称加尾缀保证全部更新。
5. 保持服务可用直到本次展示与用户查看结束，修改后沿用该服务；只清理自己启动的进程。工具失败、服务退出或页面仍旧时说明状态，提供同一预览的可点击备用链接。不得把工具调用成功当成已确认视觉效果。由谁验收、何时确认，继续遵循调用方 Skill 的既有边界。

例如真实入口 `http://localhost:3000/demo.html?lang=zh#/about`，普通修改后展示 `http://localhost:3000/demo.html?lang=zh&previewRev=1720000000000-2#/about`；做同款使用 `creatorPreview=1720000000000-2`。端口、路径和版本值来自本次任务，不照抄示例。

## 宿主验收

先展示页面，再分别修改 HTML 文案和外链 CSS，每次更新参数并调用 `present_files`，确认右侧两次均出现对应变化，同时检查已有 query 和 hash 页面仍可使用。做同款按原流程由创作者查看确认，不额外要求模型截图。未执行真实 WorkBuddy 验证时明确报告该边界。

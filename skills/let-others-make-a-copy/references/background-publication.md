# 后台发布与结果交付

用户只经历预览、一次发布确认和结果反馈。必要检查保留在 CLI/API 内，耗时命令使用宿主实际支持的后台任务或异步执行工具；不让用户逐项操作或等待验收。

## 预览期间准备

展示预览后，在后台执行带 `--preview-presented` 的未确认 publish，准备不可变终审。保留同一任务句柄、真实退出码及完整结构化结果，不把 stdout 打印给用户。用户可继续查看预览；修改页面时等原任务退出再重新准备，不能对同一项目并发 publish。准备期间没有上传授权，不能把 `presented` 当成用户认可。

只展示需要用户决定的标题、价格、作品链接及交付范围。归档、权限和摘要由 CLI/API 检查，Agent 不额外运行测试或文件审计。尚缺价格或身份等必要输入时集中提示真实缺项，不展示流水账。

## 唯一确认之后

1. 将返回的原始 `confirmCommand` 交给宿主后台执行工具，保留完整参数、Profile 和 `--state-project`。启动成功后立即反馈“正在发布”，不等待所有技术步骤才响应用户；不把启动任务等同于平台已接管。
2. 用同一任务的完成回调或结果读取能力消费输出，不启动第二个发布任务，不在前台紧密轮询。后台任务必须保留实际退出码、结构化错误及 CLI 恢复数据；不能用 `nohup`、裸 `&` 或丢弃输出冒充受管后台任务。
3. CLI 返回 `PROCESSING` 表示平台已持久化任务，展示其 `statusUrl` 后结束前台等待，平台继续处理。原站文件更新仍归 Agent，平台不会自行改写本地文件。有宿主原生完成回调或可恢复后台任务时由同一任务继续读取权威结果、同步绑定、启用按钮；没有此能力时保留原站待启用状态和同一 Publication，明确该边界，不能承诺离开后自动改本地文件。
4. 自动恢复仅限 `retryable=true` 且返回明确恢复动作，串行恢复原请求，最多两次，使用宿主后台延迟或任务调度能力，不另建定时任务。`PROCESSING` 不是失败，不触发 retry。达到上限、权限/资格/确认过期、确定性制品错误或 `STOP_AND_REPORT` 时停止并只通知需要处理的事项；不新建平行请求、不更改已确认字段。
5. 成功后使用同一 Publication 的权威 URL 启用原站按钮，不再发布源码。仅按已有授权部署外部原站。完成、失败或需要用户动作时反馈一次；无变化不反复播报进度，不追加介绍、再分发、通知绑定等问卷。

## 宿主能力边界

平台后台处理与宿主后台命令是两种能力：CLI 仍负责本地冻结、上传与服务端校验请求，宿主负责让这些命令不占用前台交互；平台在收到提交后接管异步激活。不要虚构 CLI 的 `--background` 参数，也不把服务器校验改成跳过校验。

宿主没有后台执行工具时，先简短说明“当前工具只能在本会话继续执行，平台接管后可以离开”，然后沿用唯一确认执行同一命令，不额外询问，不声称任务已脱离会话。宿主任务丢失时根据已保存状态恢复，结果不明不能宣称完成。

# 创作者入口与交付边界

创作者原站的按钮归当前创作者；交付给做同款用户的源码不继承这个按钮。平台托管页继续使用平台入口。

## 保留默认按钮，按需自定义

默认继续使用现有右下角白色圆角 pill 和点击直接复制的交互，不重新设计按钮，不额外添加弹窗。已有创作者自定义的按钮同样保留，除非创作者要求调整。

可以向创作者这样说明：“按钮的样式、文案、位置和出现时机都可以改，保留这个作品的链接就可以。例如，你可以让我改成‘制作我的版本’，或只在游戏结束后显示。”这是说明能力，不是新增必须回答的问题；用户已经提出具体要求时直接按要求修改。

只有对应作品的权威网站路径需要保留：页面链接为同一成功 Publication 的 `result.workUrl`，复制给 Agent 的邀请使用该地址对应的 `.md` 路径。按钮文案、邀请句式、样式、位置、弹窗和其他交互均可定制，不要求逐字保留默认邀请。用户要求“游戏结束后出现”时接到真实游戏结束事件，不用任意定时器冒充该事件。

沿用项目已有组件与样式机制实现自定义；不要引入通用 HTML 模板替换现有按钮。UI 文案和权威地址分开存放，通过文本属性或安全序列化写入，不拼接未经转义的 HTML。按钮须保持移动端可用及清晰键盘焦点；创作者选择弹窗时，补齐关闭操作、Escape 和关闭后归还焦点。修改后主动展示，创作者确认才更新线上。

## 可确定移除的代码块

从首次接入开始，所有仅供原作者做同款入口使用的代码都必须标记，包括按钮、弹窗、复制处理、触发事件、样式、组件定义和相关 import/挂载点。标记须独占一行，不能嵌套，起止注释形式必须相同：

```html
<!-- VICEME_CREATOR_ENTRY_BEGIN -->
<!-- 原作者入口的完整 HTML、样式和脚本 -->
<!-- VICEME_CREATOR_ENTRY_END -->
```

JavaScript、TypeScript 和 CSS 使用 `/* VICEME_CREATOR_ENTRY_BEGIN */` 与 `/* VICEME_CREATOR_ENTRY_END */`；JSX 挂载点使用 `{/* VICEME_CREATOR_ENTRY_BEGIN */}` 与 `{/* VICEME_CREATOR_ENTRY_END */}`，同样独占行。一个文件允许多对标记。不要把正常业务页面、共享依赖、赞赏、弹幕、署名或许可证包进块内；专属组件移除后，未标记代码不能还引用它。

标记只控制交付源码范围，不改变原站的按钮样式与交互。修改按钮时同步维护完整边界，不能移除标记；重复执行前先查找同一入口，禁止重复挂载。

CLI 先完整检查源码安全，再只从冻结副本移除标记块；目录和已有 ZIP 均支持。未包含标记的 ZIP 保持原始字节。标记缺失、混用或嵌套返回 `REPLICA_CREATOR_ENTRY_BOUNDARY_INVALID`，修正边界后重试。不要靠隐藏按钮、只删 DOM 而保留自动弹窗逻辑，或搜索“做同款”几个字批量删代码。旧项目已有未标记按钮时，Agent 先理解真实组件并补齐标记。

发布包采用清理后的源码摘要；最终确认和恢复始终绑定这一份不可变制品。终审的 `sourceArchive.excludedPaths` 必须为本次标记的每个源码文件返回 `reason: creator-entry-blocks`，缺少时停止确认，按主 Skill 更新 CLI 后重新生成终审，不能假定旧 CLI 已移除入口。创作者原项目不被清理，已经发布的历史版本也不改写；旧版本若仍含原作者入口，需要创作者正常发布修正版本。

## WorkBuddy 主动预览

接入及每次修改后，用 `present_files` 展示真实页面地址，并按实际 schema 提供 `files`、`cwd`、`explanation`。URL 使用 `creatorPreview=<本次修改的新值>`；有其他参数时正确追加，有 hash 时保留 hash，不把标识写进正式邀请。必要时使用项目原有服务展示真实入口，不做预览包装页。

该标识只负责显示预览按钮与更新预览缓存，不代表发布成功或授权。预览态在 iframe、file 页面或 WorkBuddy 容器中都可展示；仅预览标识存在且尚未发布时，默认点击只提示“预览效果，发布后可复制”，不写剪贴板，不产生假口令，不额外弹出对话框。正式入口在普通顶层页面显示，在未带预览标识的托管 iframe 隐藏，避免与平台入口重复。

样式修改后换新预览值再展示，不能只给旧链接并声称已刷新。工具不可用或失败须如实说明。是否显示、是否接受样式由创作者确认；自动检查不能替代 WorkBuddy 真人验收。

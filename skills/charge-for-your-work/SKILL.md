# ViceMe 网站访问接入

从用户“给网站加关注或收费解锁”的目标出发，一次收齐必要信息，在内部完成网站身份、访问规则、
价格和 SDK 配置，再修改宿主代码。创作者资格统一由 `$become-a-creator` 负责。

面向用户的文字跟随当前语言；中文使用自然白话。Website Work、平台发布配置、Work ID、功能键、
`keys.test`、`keys.live`、`configVersion`、CLI 命令和写后读回均是内部实现，不向用户展示、解释或索取。

涉及有限候选的决定时，先确认当前 Agent 平台及其实际提供的交互工具。只有当前平台明确为
WorkBuddy 且 `AskUserQuestion` 可用时才使用其可点击单选卡片；其他平台使用该平台原生的等效
交互工具。没有交互式提问工具时才退回编号短选项并提示用户回复编号。不得要求用户手打可从
发布结果或代码中列出的名称、ID 或长句；只有不存在有限候选的开放信息才直接提问。

## 流程

1. 当前以项目方式打开时，默认当前项目就是目标网站，不再询问路径；没有项目上下文时，才把网站
   项目路径与其余缺失信息放在同一轮询问。
2. 用一次交互工具调用询问所有尚未明确的开放信息：正式部署域名对应的精确 HTTPS Origin、要保护的按钮或功能、
   关注解锁还是付费解锁；选择付费时同一轮再问付费功能名称和人民币价格。不得先长时间分析项目
   再补问域名，也不得拆成多轮逐项提问。用户已经提供的内容不重复确认。
3. 第一项平台业务动作以资格守卫模式调用 `$become-a-creator`。只有它返回当前用户的
   有效商家后才继续；申请或审核未完成时停止。不得自行复制登录、申请或商家选择步骤。
4. 查看足够的项目内容，确认域名、目标入口、已有 ViceMe 接入、组件系统、样式变量和测试。域名
   只用于内部识别网站，不要求 DNS TXT、登记 Origin 或 checkout iframe 宿主验证。
5. 按 [接入参考](references/integration.md) 在内部查找或幂等创建同域名网站身份，确保可用，再以
   一次完整 SDK access 写入新增或更新关注/付费规则。保留已有 hosted 与 access 功能，写后读回，
   不轮换公开 key。任何平台对象、命令、标识和中间状态都不出现在用户消息中。
6. 保留原业务动作。在已有用户入口外加最小门控，只有 `access.require()` 返回
   `allowed: true` 后才调用原动作。找不到安全外层接缝时说明耦合并停止，不重构核心行为。
7. 使用项目既有包管理器安装 `@viceme-ai/sdk`。每个生产 `keys.live` 只创建一个客户端。宿主需要
   显示名称或价格时调用 `access.getFeatures()`，不得写死发布阶段的值。
8. 从原点击处理器调用 `access.require(featureKey)`。它按服务端决定引导登录、明确关注或
   Hosted Checkout；宿主不得直接写关注、创建结账或根据浏览器回跳自行解锁。
9. 宿主入口复用现有组件、样式变量、响应式、加载状态和错误反馈。ViceMe 的
   `<viceme-access-layer>` 保持 Shadow DOM 隔离，不穿透或套用宿主样式。
10. 测试匿名、登录未关注、已关注、未购买、已购买和取消状态；桌面验证结账留在 SDK
   Access Layer，移动端验证支付新页面被阻止或提前关闭时宿主不解锁。支付窗口失败反馈由
   Shop 的平台结账层负责，宿主只验证反馈可见，不得自行补一套弹窗或支付逻辑。同时覆盖键盘
   和减少动画状态；拒绝路径不得调用原业务动作。

完整代码和交互示例见 [references/integration.md](references/integration.md)。

## 强制边界

- 本 Skill 拥有本次网站收费目标所需的网站身份与 access 配置编排，但所有平台操作保持内部化；用户只确认网站、域名、保护目标、解锁方式，以及付费时的名称和价格。
- SDK access API 返回 `keys.test` 与 `keys.live`，没有顶层单一 `workKey` 字段。两个 key 都是永久公开且不透明的标识，不是凭据；生产宿主把 `keys.live` 传给 SDK 的 `workKey`，不得替换为 Work UUID、Product ID 或 token。
- 平台写入后必须读回确认两个 key 均存在且未轮换、完整 hosted `danmaku`/`tip` features 与完整 `accessFeatures` 均被保留，并记录精确 `configVersion`；这些检查不得出现在用户消息中。
- 浏览器代码不得包含支付密钥、webhook、Product ID、creator ID、写死金额或权益判断。
- work session 和 user token 只保存在 SDK 内存中，不写入 cookie、浏览器存储、URL 或日志。
- `access.check()` 只读；只有用户触发 `access.require()` 才能进入交互流程。
- 登录不等于关注。登录完成后重新检查，再由用户单独确认关注。
- 支付使用 Hosted Checkout；桌面结账保留在 SDK Access Layer，移动 H5/WAP 可以由结账页打开支付渠道新页面或 App。宿主不得拼接结账 URL、监听支付渠道消息或读取支付回跳参数解锁。
- 当前版本的关注/付费解锁不校验 DNS TXT、登记 Origin 或 checkout iframe 宿主；不得要求用户为
  此接入补做域名验证。work/user token 仍由 SDK 绑定到签发时的实际 Origin。
- 不改写、移动或重命名网站核心业务动作，不得改变其参数、返回值、错误或副作用。
- 不注入全局功能 CSS，不用宿主样式修改 ViceMe 层。
- 公开静态资源不能被门控追溯保护；需要强保护时只门控行为并从可信后端取资源。

## 完成检查

- 当前项目可识别时没有重复询问路径；首次询问一次收齐 HTTPS Origin、保护目标、解锁方式及条件付费信息。
- 网站身份与 access 在内部完成幂等配置，`keys.live` 被原样用作生产 `workKey`，功能键被原样使用。
- `keys.test` 与 `keys.live` 没有被合并成旧式单 key，也没有发生轮换。
- 关注与付费门控相互独立；登录后不会自动关注。
- 名称和价格来自 `access.getFeatures()`，解锁只来自新的服务端检查。
- 允许路径仍以原参数调用核心动作，拒绝、取消或支付未完成路径不调用它。
- 登录、关注、支付和取消支持键盘；桌面结账未离开 SDK 层，移动支付窗口失败时平台结账层显示反馈且宿主不解锁，返回后只根据新的服务端访问决定解锁，并报告尚未验证的微信和真实支付边界。
- 最终只向用户报告网站中的功能、价格、修改文件和验证结果，不展示平台对象、内部发布、keys、命令或协议字段。
